# ZHHZ_NEW 全高清信创交付包

这是本次最终优化的全高清信创交付包 v71，同时保留 Windows 启动脚本用于本机验收。包内不降低建筑/Twin 贴图、几何或烘焙光照质量；碰撞按当前要求不启用。

## 启动

双击 `启动ZHHZ_NEW.cmd`。需要 Windows 已安装 Node.js（同旧包要求）。脚本默认打开 `http://127.0.0.1:4192/zhhz-new.html?lightmaps=full&twinDetail=all`，Twin 后端默认 `http://localhost:5000`，可通过 `TWIN_BACKEND` 和 `ZHHZ_PORT` 覆盖。

最终运行链路只使用全场景高清 Twin。20 个高清空间块会分批加载，全部就绪前保持加载遮罩；包内不携带 `data/twin-hlod` 低模资产，运行后不下载、不渲染 HLOD 低模，移动视角不会发生低模/高清切换。信创/类 Linux 环境可执行 `bash 启动ZHHZ_NEW.sh`；Windows 仍可双击 `.cmd`。

## 本次已接入

- 默认全量驻留 UE 烘焙 Lightmap：189 张源 atlas 的 378 个 layer tile 逐像素无损放入 12 张 4096 superatlas，移动视角不主动卸载，避免区块边界突然变暗；绑定仍为 12,012/12,012。
- 建筑静态网格已按材质与 4096 superatlas 页合批；每个批次保留逐顶点 UE Lightmap 解码参数，几何三角形和源 tile 像素均未降低。
- Twin 空间块按实例/材质合批，保留实例根节点、实时 reset/delta 更新和共面修复元数据。
- Twin 高清模型全量加载，并在实例根内按材质/顶点布局/50 米空间格合批；50 米分格在完整 20/20 高清集上复测后作为默认值：比 20 米少约 80 个驻留合批网格，当前内置机位 DrawCall 约少 3.6%，同时保留空间边界和高清几何。可用 `?batchCell=20` 做更保守视锥裁剪对照；加载完成前保持遮罩，完成后才进入展厅，避免先出现空洞或低模替换。
- 第二轮无损优化：建筑 548 个带逐顶点 Lightmap 解码的候选网格仅按同材质、同 atlas、同空间格合并，当前机位稳定减少 6 个静态提交；全量 Lightmap 首次编译并上传后冻结 uniform 更新，避免每帧重复写入，不改变任何像素、材质或光照。
- 高清 `.gltf/.bin` 使用 2 路加载和最多 3 次重试；任一块失败时不揭示半成品场景。
- 反射探针在连续移动时保持当前探针，只有切换 UE QA 机位才强制更新。
- OntoTwin RuntimeDock 按插件源码收口为底部居中的 870×158 玻璃面板：标题为“控制面板”，页签顺序为“主页 / 漫游 / 空间 / 业务 / 编辑”，选择器标签为“人物 / 路线”；漫游区提供“全局 / 过肩 / 第一 / 准星”视角按钮和“换肤 / 返回 / 重播 / 重载”快捷操作（“重载”按原插件仅在有待重载状态时显示）。主页会退出漫游并恢复 UE 启动机位。第一人称准星同时支持 Dock 按钮和 E 键，非第一人称时按钮保持禁用。过肩相机按 UE 胶囊中心 + TargetOffset 复刻，RenderPeople 的 UE -90° 网格偏移已换算为浏览器 0°，右键按住可环绕观察。
- 小地图按插件交互补齐为 320×240 内容区和稳定切换按钮：展开/收起、单击预览、双击传送、返回原位置；地图显示路线、路径点、Twin 实例和人物标记。插件源码没有常驻“跟随/定位”按钮，网页不虚构额外控件。
- 路线按后端路径点运行；21 个路线解说 WAV 已随包放入 `data/narration/`，本地优先播放，缺失时才请求后端；音频受浏览器自动播放策略限制时会保留字幕。God/过肩/第一人称 HUD 提示按原插件动态切换，P 暂停/继续、WASD 接管、R 返回线路、E 准星、Space 跳跃、跳过解说均与 UE 路线状态一致。
- 本版 UI/交互修复：点击视口中的 Twin 高清实例会显示该实例的名称、类型、实例 ID、场景路径和介绍，并提供定位/编辑入口；点击屏幕或首次交互会同时解锁两路主屏视频。天花板屏 `MI_MainScreen_H` 与立面屏 `MI_MainScreen_V` 分别绑定 `MainScreen_H.mp4` / `MainScreen_V.mp4`，两路从同一时间零点启动并持续校正漂移，用于复刻原插件的联动裸眼 3D 播放链路。两块导出屏的 glTF UV 均存在上下镜像，已对 H/V 两路统一增加显式垂直采样修正，避免立面正确而天花板倒置。
- 路线解说已改为复用单个持久 audio 元素：每个航点的可播放片段在 `ended` 后推进到下一片段/下一航点，不再只播放首句；本地 WAV 出错时才回退后端，自动播放被浏览器拦截时保留待播放片段并在下一次用户手势恢复。
- 6 个 RenderPeople 人物均已导出为独立、带纹理且带动画的 glTF；每个人物均包含 Idle + Walk 两个 clip。由于 UE 导出 clip 与浏览器网格的骨架基准不同，生产默认使用已验证的 95 骨骼程序化 Idle/Walk 姿态，原始 glTF clip 仅保留在 `?gltfAnim=1` 实验开关，不再让错基准动画导致人物消失或手臂镜像。
- 后端当前仍返回两个历史人物目录项（Observer/Manny），因包内没有对应的带动画高清资源，运行时已过滤为 6 个可交付 RenderPeople 角色，不会让用户误选后回退到旧 `roamer.gltf`。
- 后端暂时不可达时，人物选择器仍使用这 6 个本地打包角色；离线路径不会显示旧程序化 T-Pose 人物，路线数据则等待后端恢复。
- F10 进入运行时编辑器（与 F7 漫游互斥）：从 Twin 实例列表选中对象后可用方向键移动，Ctrl+Z/Ctrl+Y 或按钮撤销/重做，标记隐藏，并执行保存/取消全部修改；再次按 F10 或编辑器右上角 × 退出。
- 人物姿态修复：生产默认使用已验证的程序化 Idle/Walk 姿态，避免 UE 导出动画的组件空间轨道直接套到 glTF 骨架后产生 T-pose、肢体塌陷或左右镜像；第三人称跟随距离已固定为可完整看到人物的最小安全距离。原始 glTF 动画仅可通过 `?gltfAnim=1` 调试，不作为交付默认。

## 当前验收边界

包内数据沿用已验收的静态场景和 Twin 分块；建筑/Twin 合批、6 人物材质/动画、三视角、路线/字幕/语音、小地图、Twin 点击介绍和双屏联动已在本 Windows 包验证。四人共享同一套 95 骨骼协议的 Idle/Walk clip，并非各自独立 source-native 录制；若验收硬性要求每人独立 clip，需要另做 UE IK Retarget 资产变更。`?lightmaps=stream` 仅用于后续 X300 显存压力试验。

合批会增加静态顶点属性（建筑包约 982 MB geometry buffer），因此必须在 X300 上同时观察显存/系统内存；若目标机内存不足，优先改为分区驻留，不能用降低 Lightmap 质量替代。

性能和完整性记录位于运行目录的 `06_acceptance/windows-four-view-metrics.json`；Windows 浏览器可提供 DrawCall、三角形、纹理数量和 Lightmap 显存上界估算。浏览器未暴露 JS heap 或可靠 GPU 毫秒时，报告会明确标记为不可用，不用 FPS 代替这些指标；X300 必须在目标浏览器上重新记录。

固定机位性能复测可在网址后加 `&benchmark=views&camera=project_anchor_2`（也可换成 `interior_east`、`interior_west`、`overview_southeast`）。v71 单页干净样本：20/20 高清区块、12/12 superatlas、HLOD=0，`twinBatchCellSize=50`、`renderCalls=2,221`、`twinBatchRenderMeshes=2,164`、`twinBatchDrawsReduced=968`、`renderTriangles=28,618,059`、`lightmapCallbacksFrozen=true`；本机单页样本约 49–60 FPS，帧时间 P95 约 16.8–33.5 ms（浏览器/GPU 争用会影响数值，不能替代 X300 实测）。并行打开多个 WebGL 页面不计入指标。该参数只暂停漫游 tick 对 QA 机位的覆盖，不改变正常启动的漫游逻辑。
