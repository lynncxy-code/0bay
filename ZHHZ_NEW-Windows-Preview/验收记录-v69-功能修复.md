# ZHHZ_NEW Windows 预览包 v69：功能修复与性能记录

日期：2026-09-03  
对象：`07_package/ZHHZ_NEW-Windows-Preview`  
范围：Windows 本机预览；碰撞检测按当前要求暂不修改。

## 交付前结论

本版已把四个问题合入当前包，并完成单页干净浏览器冒烟验证。运行链路继续保持“全高清 Twin + UE 烘焙 Lightmap”，没有引入低模/HLOD 替代，也没有把屏幕贴图降采样。

## 四项修复

1. **人物动作**：生产默认切换为已验证的 95 骨骼程序化 Idle/Walk 姿态，修正手臂外展、T-pose、肢体塌陷和左右镜像问题；第三人称过肩距离固定为可完整看到人物的安全距离。原始 glTF 动画保留为 `?gltfAnim=1` 调试开关，不作为交付默认。
2. **双屏联动**：按 UE `MainScreenVideoRuntime` 的材质映射，立面屏 `MI_MainScreen_V` 播放 `data/MainScreen_V.mp4`，天花板屏 `MI_MainScreen_H` 播放 `data/MainScreen_H.mp4`。两路视频在同一用户手势后从时间零点启动，并用 120 ms 阈值持续校正漂移；针对 V 屏导出 UV 上下镜像，增加显式垂直采样修正，H 屏保持原方向。验证时 `videoScreens=2`、`videoSync=playing`、漂移约 18–210 ms（取样期间视频解码调度会造成短时抖动）。
3. **Twin 点击说明**：视口点击先射线命中高清合批网格，再利用实例根节点/作者边界回溯到 Twin 实例；验证点击后 `twinSelected=ue_CF34D6CB-4FB9-CBAC-0236-AE98CCF7D6B9`，详情卡可见，显示“东南展区·组合展品 18”、类型“展品”、实例 ID，并提供定位/编辑入口。
4. **路线语音续播**：改为复用一个持久 `<audio>`，每段 `ended` 后推进到下一段并继续播放；本地 WAV 优先，加载失败才回退后端。用户手势可解锁浏览器自动播放。验证选择“解说路线 · 21 点”并点击“重播”后，首段状态为 `narrationAutoplay=playing`、`narrationSource=local`；继续观察后 `narrationPlayedSegments=2`、音频仍来自本地，证明后续片段已继续播放。

## 高清与 DrawCall 验证

干净单页样本（`http://127.0.0.1:4193/zhhz-new.html?lightmaps=full&twinDetail=all&roam=1&camera=interior_east&collision=0`）：

| 指标 | 结果 |
|---|---:|
| 高清区块 | 20/20 |
| `twinHighReady` | `true` |
| HLOD | 0 块 / 0 DrawCall |
| Twin 源网格 | 3,132 |
| Twin 合批网格 | 2,308 |
| Twin 合并减少提交 | 824 |
| `renderCalls` | 2,133 |
| `renderTriangles` | 26,585,887 |
| `twinInstances` | 508 |
| Lightmap 常驻 | 12 张 superatlas |
| 视频屏幕 | 2 |
| 角色模式 | `procedural-walk-v2` |
| 本机单页 FPS | 约 49–56 |
| 本机帧时间 P95 | 约 18–35 ms |

20 米空间格是当前默认值。50 米格虽然理论上少一点合批网格，但实测帧时间更不稳定，因此不作为默认。优化只做空间/材质合批和屏幕材质缓存，保留逐顶点 Lightmap 解码参数、几何三角形、高清贴图和实例可编辑地址；没有通过降分辨率、HLOD 或视口外删减来“伪优化”。

## 已知边界

- 浏览器自动播放策略可能在没有用户手势时阻止语音/视频；本版会保留待播放片段，点击页面或操作控制面板后恢复。
- `collision=0` 仅用于本次验证，碰撞体/上下楼梯功能尚未在本阶段改动。
- 本机 FPS 只能作为 Windows 端参考，X300 必须在单页、无并行 WebGL 页面条件下重新记录。
